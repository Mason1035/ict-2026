## 数值规范的建议修订

建议后续联合版本改为 ESP32/Python 均 binary64：原始值转 double，插值、贡献、奖励、加权及比较全过程不落回 float32；C++ 编译时静态检查 sizeof(double)==8、is_iec559、digits==53。常量避免 f 后缀，禁用 fast-math 和重排，统一是否允许 FMA；建议先禁用 FMA 收缩，按 Python 参考 tilt→vibration→moisture→growth 顺序累加，再加奖励，再 clamp，再分级，不提前舍入。

double 不能单独保证跨平台逐位一致，三角函数、滤波及编译行为仍需对拍。原 V0.1 atol/rtol 仅保留为待测初值，不因 double 自动收紧或宣布通过；null、mask、等级、状态始终精确相同。新增 30/60/80 的 binary64 nextafter 两侧向量（替代作为主精度的 float32邻值），并测 0/100、极小正贡献、clamp、共识奖励。任一等级/位号不同仍判失败。

## NVS 锁存实现的验收补充

接受 NVS+CRC32+魔数/版本作为实现方向。CRC32 检测意外损坏，不认证来源；平台 API 的写入承诺不等于多键事务自动成立。建议锁存状态以单个版本化 blob 提交，或明确双槽/世代提交方案；持久化设备身份、最高等级、触发上下文和配置关联，校验长度/CRC/字段/版本。

首次空、有效锁存、损坏/不支持版本必须分开；损坏进入独立故障待人工核查，不能伪装已知安全或虚构灾害等级。重启恢复有效锁存后重新计恢复时间；恢复蜂鸣器/LED与 ACK 静音的具体策略须 A/C 确认。持久化 ACK/CLEAR 及掉电时序也要测试：CLEAR 未提交成功不能报告解除成功；重试必须幂等。避免 20Hz 每循环写 flash，只在必要状态转换时写；写入失败不取消本地指示。

Host 测试不能证明 NVS 掉电原子性。另需实板在触发保存、ACK保存、CLEAR保存期间断电复测，以及 CRC错误、旧版本、错误设备、空记录测试；保留实测证据。

## GPIO21 本地交互建议

短按=本地 ACK，静音但不解除锁存；长按>=3000ms仅在已ACK且恢复条件持续满足时申请CLEAR。A 提供按键有效电平/上拉及消抖实测参数，本包不猜测这些值。

一次按压只生成一个事件：短按在释放时且未达到长按门槛才产生；长按触发后释放不再生成短按。CLEAR 必须在 RECOVERY_PENDING 中重新开始一次新按压，ACK与CLEAR不能同次手势完成；上电已按住、恢复前开始按住均不算有效CLEAR。长按期间一旦缺测/升高/恢复条件中断立即取消计时，需重新满足恢复条件并新按一次。使用单调时间，不用任务循环计数。

ACK动作本身不是身份认证；GPIO本地可达性属于实际权限边界。串口测试触发仅限显著标记的TEST_ONLY/HIL构建和受控本地接入，不能留下正式运行的未授权CLEAR后门；禁用远程映射，生产模式拒绝测试注入。
