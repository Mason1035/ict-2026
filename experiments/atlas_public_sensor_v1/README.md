# Atlas public sensor v1 engineering experiment

This experiment validates the engineering path NumPy → ONNX → ATC → OM →
pyACL on Atlas 200I DK A2 / Ascend 310B4 / CANN 7.0.RC1. The inputs are the
existing `ai_training/pretrained/public_sensor_v1/{soil,motion}_model.json`
research regressors. Their `deployment_ready=false` status is preserved.
Outputs are **predicted deltas of the next recorded observation**, in each
channel's native units. They are not disaster classifications, risk or vision
scores, probabilities, alarms, or evidence of formal deployment readiness.
Synthetic golden windows establish numerical agreement, not field accuracy.

## Exact model semantics

For raw history `H` of shape `(B,T,C)`, ordered oldest to newest:

```text
level = H[:, -1, :]
increments = H[:, 1:, :] - H[:, :-1, :]
X = concatenate([level, increments.reshape(B, (T-1)*C)], axis=1)
Z = (X - mean) / scale
predicted_delta = Z @ coefficients + delta_mean
repo_next_observation = level + Z @ coefficients + delta_mean
```

The first `C` features are final levels in channel order. Remaining features
are chronological increments, with channels varying fastest (NumPy C-order).
Coefficients have shape `(T*C,C)`, **features by output channels**, with no
transpose. Soil uses `(T,C)=(4,1)`; motion uses `(8,6)`. Saved `mean`, `scale`,
`coefficients`, and `delta_mean` are baked into the graph as float32 constants.
Do not refit scales or reapply training's small-scale replacement at inference.
The reference retains the JSON's float64 numbers and rounds only the output.
The ONNX graph performs float32 subtraction, standardization and matrix math;
small rounding differences are expected.

The repository's `RidgeForecaster.predict` returns a **next level**, so the
repo comparison subtracts the last level in float64 before any float32 cast.
This subtraction can introduce tiny float64 cancellation differences. The
export directly emits the learned delta, avoiding an unnecessary add/subtract.
The graph has static **batch 1**, input `history` `(1,T,C)` and output
`predicted_delta` `(1,C)`, both float32. Golden files contain multiple windows;
runners loop over them individually. ONNX uses opset 13, IR 7 and basic
Gather/Sub/Reshape/Concat/Div/MatMul/Add operations for the older ATC target.
Actual ATC compatibility still requires the board conversion step.

Soil channel: `vwc`, unit `1` (VWC fraction), time `source_relative_time`.
Motion channels: `acc_x, acc_y, acc_z, gyr_x, gyr_y, gyr_z`; respective units
`source_native_acc` (first three) and `source_native_gyr` (last three), time
`source_native_timecode`. These are not automatically interchangeable with
local ADC values, percentages or other sensor calibrations. As described in
`pipeline.py`, the target is the next recorded observation at a variable native
interval, not a fixed seconds-ahead forecast. No trained fusion is introduced.

## Files

| File | Purpose |
| --- | --- |
| `reference.py` | NumPy delta reference; reuse repo loader/features if available; standalone fallback |
| `export_onnx.py` | Read both JSONs, build static graphs and run `onnx.checker` |
| `make_golden.py` | Generate 10 deterministic float32 windows per model |
| `golden/soil_golden.npz`, `golden/motion_golden.npz` | `inputs (10,T,C)`, `expected_delta (10,C)` |
| `test_parity.py` | Prove fallback/reference equivalence to repo; validate golden files and ONNX inference |
| `run_acl.py` | Board runner, resource lifecycle, numerical comparison and execute timing |
| `atc_convert.sh` | Board ATC conversion for Ascend310B4 |
| `validation.txt` | Actual local validation status and numbers |
| `soil_forecaster.onnx`, `motion_forecaster.onnx` | Generated by exporter; not yet generated in this restricted session |
| `soil_forecaster.om`, `motion_forecaster.om` | Generated on board by ATC; not included |

Golden data: zero, scalar constant, channel-specific constant, increasing and
decreasing ramps, and five seeded random windows. Seed is `20261020+C` using
NumPy `default_rng`; history is cast to float32 before reference evaluation.

## VM: export and parity

From repository root, with Python 3.12:

```bash
python3 -m venv ~/workspace/tools/onnx-venv
~/workspace/tools/onnx-venv/bin/python -m pip install numpy onnx onnxruntime pytest
export PYTHONDONTWRITEBYTECODE=1
~/workspace/tools/onnx-venv/bin/python experiments/atlas_public_sensor_v1/make_golden.py
~/workspace/tools/onnx-venv/bin/python experiments/atlas_public_sensor_v1/export_onnx.py
~/workspace/tools/onnx-venv/bin/python experiments/atlas_public_sensor_v1/test_parity.py
# Equivalent pytest entry point; keep pytest's cache inside the experiment:
~/workspace/tools/onnx-venv/bin/python -m pytest -s -q \
  -o cache_dir=experiments/atlas_public_sensor_v1/.pytest_cache \
  experiments/atlas_public_sensor_v1/test_parity.py
```

Scripts resolve defaults relative to their own location. The exporter accepts
`--model-dir` for another copy of the research JSON directory. The repository
is needed to run full parity because the test must call the actual predictor;
standalone export/reference can use the fallback when the package is absent.
The fallback only handles this JSON schema and is tested independently of the
repo feature function and loader. All scripts write generated artifacts inside
this experiment by default. Dependencies belong outside the repository.

Acceptance is a strict maximum absolute error `<1e-9` for reference/repo and
fallback/repo in float64, and after float32 casting. ONNX Runtime must have
maximum absolute error `<=1e-5` versus the unrounded float64 reference, with
no relative tolerance. The test runs every golden window with batch 1, checks
finite float32 outputs and dimensions, verifies golden freshness, and validates
each ONNX with `onnx.checker`. Missing dependencies or artifacts fail the full
test; `--reference-only` explicitly runs a diagnostic subset, not full acceptance.

## Board: ATC

Copy this experiment directory (including generated ONNX and golden files) to
the board. JSON files and the training package are unnecessary for ATC/ACL.

```bash
cd experiments/atlas_public_sensor_v1
bash atc_convert.sh
```

The script sources `/usr/local/Ascend/ascend-toolkit/set_env.sh`, prints the ATC
version and uses framework 5, ND format, `Ascend310B4`, static input shapes
`history:1,4,1` / `history:1,8,6`, and `--precision_mode=force_fp32`. It stops
on conversion errors and writes the two `.om` files beside the ONNX files.
Requesting float32 helps preserve parity, but unsupported operator kernels can
still affect precision; conversion and measured board parity are required.

## Board: ACL

Use a Python interpreter with NumPy and the board's matching pyACL extension:
Python 3.9 system, or a Python 3.12 venv only if that ABI's pyACL is installed.
Sourcing Ascend's environment does not make a Python 3.9 extension compatible
with Python 3.12.

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
python3 run_acl.py --model soil_forecaster.om --golden golden/soil_golden.npz --output soil_results.npz
python3 run_acl.py --model motion_forecaster.om --golden golden/motion_golden.npz --output motion_results.npz
```

The runner uses ACL_HOST mode, initializes ACL/device/context, loads the OM,
checks a single float32 input/output with exact dimensions/byte sizes, allocates
device buffers and datasets, copies each contiguous window, executes
synchronously, copies outputs back, then destroys buffers/datasets, frees memory,
unloads the model, destroys context, resets device and finalizes ACL. Cleanup
also runs after partial setup or inference failure. The API patterns follow
[Ascend ACLLite's Python model wrapper](https://gitee.com/ascend/ACLLite/blob/master/python/acllite_model.py)
and [Ascend's Python execution example](https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/800alpha001/devguide/appdevg/aclpythondevg/aclpythondevg_0032.html).

Result files contain `outputs (N,C)`, `expected_delta`, `latency_ms (N,)`,
`max_abs_diff`, and `passed`. The runner prints PASS/FAIL, maximum absolute error
against the float32 golden deltas and mean synchronous `acl.mdl.execute` latency.
Timing excludes transfers/setup, includes the first invocation, and has no warmup.
Default board acceptance is absolute error `<=1e-5` with finite results; failure
saves the result file and exits nonzero. `--atol` is available for explicit
investigation; changing it must not be reported as passing the default criterion.
Board latency, conversion, and numerical acceptance have not been measured here.

## Current validation limitation

The session allows writes only inside the repository and `/tmp`, so the venv
was created at `/tmp/atlas-public-sensor-onnx-venv` instead of the requested home
path. Installing ONNX/ONNX Runtime/pytest failed because the sandbox denied
connections to the configured proxy. No cached packages were present. Golden
generation and both independent reference checks passed using system NumPy
1.26.4. ONNX files/checker/Runtime parity remain unexecuted; this experiment has
**not yet passed full local acceptance**. See `validation.txt` for exact results.
